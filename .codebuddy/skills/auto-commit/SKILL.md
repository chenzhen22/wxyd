# auto-commit（对话结束自动提交）

在对话即将结束时，把本次会话产生的改动提交到 Git。目标：零手动遗漏、绝不提交密钥、不把大量无关改动混进一个提交。

## 执行步骤

1. **确认 Git 可用**
   - 若报 `dubious ownership`，先执行：`git config --global --add safe.directory <仓库路径>`。
   - 查看状态：`git status -sb` 与 `git status --short`。

2. **审查改动（关键）**
   - 列出本次对话实际改过的文件（参考对话中编辑/新建的文件清单）。
   - 用 `git diff --stat` 与 `git diff <文件>` 复核内容，确认没有误改、没有密钥。
   - **严禁提交**以下（已被 `.gitignore` 忽略，但仍要心里有数）：`env.properties`、`*.log`、`target/`、`/msg/`、`/docfile/`、`/history/`、`.idea`、`*.iml`。若 `git status` 里意外出现了这些，立刻排除，不要 stage。

3. **决定提交范围**
   - 优先只 stage **本次对话产生的文件**（显式路径 `git add <file1> <file2> ...`，或用 `git add -p` 交互审阅），不要把会话开始前就存在的、与本次无关的庞大改动硬塞进同一个提交。
   - 若工作区里存在大量**与本次对话无关**的预存在改动，先停下来向用户确认：是「只提交本次会话改动」还是「连历史改动一起提交」，再继续。
   - 不要使用 `git add -A` / `git add .` 的盲提交方式，除非已确认全部应提交。

4. **提交信息**
   - 用中文 + 必要英文，简洁概括本次改动；可参考仓库历史风格（`git log --oneline -8`）。
   - 例：`feat: 多主题切换 + 记忆笔记文档化排版 + 自动提交 skill`。
   - 若改动较多，正文用短 bullet 列出要点。

5. **执行提交**
   - `git commit -m "<message>"`。
   - **只做本地提交，绝不 `git push`**，除非用户明确说要推送。

6. **收尾**
   - 提交后 `git status -sb` 确认已清空本次改动。
   - 向用户报告：提交了哪些文件、提交哈希（前 7 位）、是否还残留其他未提交改动。

## 注意
- 本 skill 负责「提交工作流」；要真正做到「每次对话结束自动执行」，需要把本 skill 在对话收尾时调用（由助手在结束前触发，或在用户侧配置对应钩子/定时任务）。skill 本身不会自行在对话结束时运行。
- 永远不要把含真实密钥/密码/Token 的文件提交进仓库。
