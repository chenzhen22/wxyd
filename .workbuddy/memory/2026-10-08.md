## 知识库 PRD：Q1 决策定稿（全文检索范围）

**用户拍板**：索引**不要存他人 public 笔记全文**。

**落地方式**：`note_index` 新增 `content_indexed` TINYINT 标志位

| 场景 | 行为 |
|------|------|
| 搜自己的笔记 | 标题 + 正文全文命中 |
| 搜他人 public | **仅标题命中**（正文不入库） |
| 搜他人 private | 零命中（红线） |

- 写入侧判定：仅当 `ownerId == 当前登录用户` 才写 `content` 并置 `content_indexed=1`；
  他人 public 置 0 且 content 留空。`rebuildIndex` 重建时按同一规则回填。
- 这是**数据最小化**决策：public 只代表"可读"，不代表"可被全文索引"。
  正文进索引 = 库里多一份可检索副本（备份/误查/DBA 直连场景），与 private 红线的防御深度不匹配。
- 好处：将来若放开，只需重建索引 + 放开查询条件，**表结构无需变更**。

**🔴 实测抓出的越权漏洞（已修，务必记住）**：
初版正文匹配条件只写了 `content_indexed=1`，**漏了 `owner_id=#{currentUserId}`**，
导致 B 用户 `field=content` 能搜到 A 的 public 笔记正文 —— Q1 形同失效。
正确写法：`owner_id=#{currentUserId} AND content_indexed=1 AND content LIKE ...`。
**关键教训**：Q1 的保证来自**查询条件**，不是来自「库里没有别人的正文」——
public 笔记正文本来就该入库（属主要检索自己的笔记），
所以「查库统计他人正文行数」这种自检**发现不了这个漏洞**，必须走真实检索路径验证。
`/note/audit/foreignContent` 已改为：从他人 public 正文取样词 → 用真实检索路径验证零命中。

**踩坑**：
1. `javax.annotation.Resource` 与 `org.springframework.core.io.Resource` 同名，
   NoteDataService 必须用全限定名 `@javax.annotation.Resource`（原文件本来就这么写，别改回 import）。
2. 远程 MySQL 开了 `only_full_group_by`：listTags 的 `count(*)` 必须配 `group by tags`，否则 500。
3. curl 测中文关键词必须用 `--data-urlencode`（或浏览器），直接传中文会 400，那是测试脚本问题不是产品 bug。
4. 注册用户默认 status=1 待审批，需 admin 调 `/approveUser` 才能登录测第二用户。
